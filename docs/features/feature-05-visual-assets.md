# Feature 05: 可爱视觉系统与内置资产

## 目标

落地 Sakurajima 的视觉系统、桌宠立绘、状态表情、图标和主题化 UI。

## 核心行为

- 应用整体风格统一
- 桌宠具备基础状态差异
- 图标和按钮风格与角色形象一致

## 资源策略

- 优先使用开发阶段生成的统一风格资产
- 如图片生成环境不可用，先以内置 SVG 方案保底，后续可替换

## 实现约束

- companion 与 panel 共用同一套品牌色、图标与角色资产
- 资产文件命名与角色状态一一对应，避免 UI 侧推断式拼接
- 不因缺少生成式图片环境阻塞可运行版本交付

## 实现结果

- 已内置 `idle / happy / thinking / sleepy / error` 五套 SVG 角色状态图
- 已内置 `sakura-mark` 品牌标识，并接入侧边栏与设置头部
- companion 已从临时 CSS 脸谱替换为正式本地 SVG 立绘
- 聊天空态、品牌锁定区和整体面板已切换到统一的资产与配色系统
- 已保留后续替换点，未来可在不改组件结构的情况下换成生成式资产

## 验证结果

- `npm run typecheck`：通过
- `npm test`：通过
- `npm run build`：通过
- `npm run dev`：启动通过，SVG 资源导入未引发运行期错误

## 验收标准

- UI 主题完整
- 桌宠和图标风格一致

## 安全与严谨性审查

- 本次资产全部为仓库内置 SVG，不依赖运行时远程拉取，避免引入额外供应链面
- 由于缺少 `OPENAI_API_KEY`，本轮未执行生成式图片调用；采用可维护的本地 SVG 方案作为稳定回退
- 角色状态文件显式命名，避免 renderer 端拼接未验证路径
- SVG 作为静态资源导入，不通过 `dangerouslySetInnerHTML` 内联，降低渲染注入风险
